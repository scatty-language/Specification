# Operators

In Coggy all operator behaviors for `Data` types are generated by the compiler via declarative field markers.

## Identity and Equality

The `$` modifier explicitly marks a field as part of the Data's Identity. It dictates the behavior of the structural equality operators (`==` and `!=`).

* **Default Behavior**: If NO fields within a `Data` declaration are marked with `$`, the compiler generates equality operators that compare ALL fields.
* **Identity Behavior**: If ONE OR MORE fields are marked with `$`, the compiler generates equality operators that compare ONLY the marked fields. All unmarked fields are MUST be ignored during equality checks.
* **Variant Fields**: Variant Field MAY be marked with `$`. The generated equality operator MUST compares the active variant tag and its payload.

```C#
User 
{
    // Identity fields
    $Id: Int;
    
    // Ignored during '==' and '!='
    Role: String;
    
    // Variant identity
    $Status { Active, Banned(reason: String) }
}

userA := User { Id: 1, Role: "Admin", Status: .Active {} };
userB := User { Id: 1, Role: "Guest", Status: .Active {} };

// Evaluates to 'true' because 'Id' and 'Status' match
if userA == userB 
{
    Console.WriteLine("Same Entity and Status");
}
```

## Mathematical Operations

The `#` modifier explicitly marks a field as a participant in mathematical operations.

The compiler automatically derives all standard mathematical operators (`+`, `-`, `*`, `/`, `%`) and their compound assignment variants (`+=`, `-=`, etc.) for the enclosing `Data` type.

* **Same-Type Restriction**: Generated operators MUST accept two operands of the exact same `Data` type.
* **Left-Operand Dominance**: When evaluating an operation (e.g., `A + B`), the compiler:
  1. Creates a copy of the left operand (`A`).
  2. For every field marked with `#`, applies the operator (`A.Field + B.Field`) and assigns it to the copy.
  3. All unmarked fields retain their original values from the left operand (`A`).
* **Type Constraints**: Fields marked with `#` MUST inherently support mathematical operators.
* **Variant Prohibition**: Variant Fields MUST NOT be marked with `#`.

```C#
Transform 
{
    Name: String; // Retained from left operand

    #X: Float;
    #Y: Float;
}

t1 := Transform { Name: "Start", X: 10.0f, Y: 5.0f };
t2 := Transform { Name: "Offset", X: 5.0f, Y: 5.0f };

// result is: 'Transform { Name: "Start", X: 15.0f, Y: 10.0f }'
result := t1 + t2; 
```

## Inline Fields and Operator Delegation

Because declarative operators are internally generated as methods, their interaction with Inline Fields follows standard Method Shadowing rules.

* **Implicit Delegation**: If a `Data` type does NOT declare any fields with `$`, but contains an inline field `@Field` that provides a custom `==` operator, the parent type transparently delegates all equality checks to the inline field's operator. The same rule applies to `#` for mathematical operations.
* **Explicit Shadowing**: If the parent `Data` type explicitly marks ANY field with `$` or `#`, the compiler generates a new operator for the parent. This shadows any corresponding operators provided by its inline fields.
* **Ambiguity Resolution**: If a `Data` type contains multiple inline fields that provide the same operator, and the parent does NOT explicitly shadow it by marking its own fields, any usage of that operator is FORBIDDEN.

```C#
PhysicsData 
{
    #Velocity: Float;
    $Hash: Int;
}

Player 
{
    // Implicitly provides '#' (+) and '$' (==)
    @Physics: PhysicsData;
    
    Name: String;
}

Enemy 
{
    @Physics: PhysicsData;
    
    // Explicit shadow: overrides the inline '$' (==)
    // Enemy equality will ONLY check 'Id', completely ignoring 'Physics.Hash'
    $Id: Int;
}

playerA := Player { Physics: PhysicsData { Velocity: 5.0f, Hash: 1 }, Name: "A" };
playerB := Player { Physics: PhysicsData { Velocity: 2.0f, Hash: 1 }, Name: "B" };

// 'true' because 'Physics.Hash' is 1 for both. 'Name' is ignored
isSamePhysics := playerA == playerB;

// Evaluates via the inline field's '#' markers
// Result: 'Player { Physics: { Velocity: 7.0f, Hash: 1 }, Name: "A" }'
playerC := playerA + playerB;
```

## Relational Operations

Coggy does NOT implicitly generate relational operators for custom `Data` types. If sorting or magnitude comparison is required, the type MUST explicitly implement the `~Comparable` standard interface.

* **Prohibition**: Overloading `<` or `>` directly via syntax modifiers is FORBIDDEN.

```C#
~Comparable 
{
    // Must return -1, 0, or 1
    Compare(@, other: @) -> Int;
}
```
